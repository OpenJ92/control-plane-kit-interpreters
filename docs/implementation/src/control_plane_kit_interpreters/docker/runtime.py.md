This owner interprets selected Core runtime-effect requests into Docker operations and bounded results. Operations owns durable dispatch and approval; this module owns provider effects, material/ownership preconditions and post-effect observations. execute validates the request's intent relationship before dispatch. execute_with_authority additionally binds the selected local or remote client and accounts for client-close uncertainty.

StartNode checks existing recipient identity, resolves authorized delivery/pull material, admits the canonical image and prepares file ownership before network/container creation. Its phase/suboperation diagnostics distinguish where the boundary failed but do not imply transactional rollback. In particular sdk-create can include the installed high-level SDK's follow-up inspect. Do not replay an uncertain effect or delete partially acquired resources merely because a final result is unavailable.

Retained storage and ephemeral compute have distinct lifecycles. Stop/remove container paths check ownership; they do not turn retained data into disposable cleanup. Reconcile and Start differ in allowed prior-plan ownership and reuse. Keep selected secret grants, local socket delivery, remote connection material, image identity and actual running/network postconditions explicit. Read the exact branch before changing a shared helper: health verification, runtime-private probes and source effects use different evidence contracts.

Private naming/fingerprint helpers implement this interpreter's resource association; they are not a new public topology language. Callers must not invoke preparation helpers as read-only diagnostics: preparing material can create provider resources. The synthetic fixture can demonstrate one current request composition, not deployed-CPK equivalence or historical retry safety.
