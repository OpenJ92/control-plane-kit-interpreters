[Source](../../../../../src/control_plane_kit_interpreters/docker/sdk.py) is the Docker representation/effect boundary used by the runtime interpreter. It translates explicit mounts, aliases, ports and authority into SDK calls and inspects provider facts. It does not own Operations admission, durable history or retry decisions. Preserve this separation when adding convenience helpers.

`create_container` constructs request arguments, constructs endpoint aliases, then calls the installed high-level `containers.create`. The wrapper itself returns no container value. Its `sdk-create` diagnostic boundary includes whatever the installed SDK does before that high-level method returns; it is not a label for an HTTP POST alone. In the Docker7.2.0 implementation exercised by #141, creation includes a follow-up inspect. An exception at this boundary therefore does not prove that no container was created. See the [creation evidence relation](../../../../architecture/docker-creation-evidence.md).

Retained volumes use the SDK volume mapping; configuration and protected-file deliveries use read-only `Mounts` with a `content` subpath. Explicit bind mounts and host publications are separate inputs. Do not normalize these into one representation without checking both requested and effective provider state. Image matching uses canonical reference/identity rules, not an arbitrary familiar tag. Numeric image-user inspection and supplementary groups affect file recipients; preserve their distinction.

Client construction may be lazy and runtime-authority-specific. TLS temporary files are cleaned on construction failure or explicit close; this is a construction/close lifetime, not a timed lease. Secret values must not enter command arguments or exception reports. Materialization/probe helpers have their own image, networking, output, timeout and cleanup contracts. Before changing a helper, inspect its caller and the exact helper method rather than assuming recipient-container policy applies to it.

Contract-bearing dependencies include Core configuration/secret/authority values and the installed Docker SDK. [pyproject.toml](../../../../../pyproject.toml) selects Core and permits a Docker version range; #141's tested7.2.0 is evidence, not a universal pin. Verify the actual consumer's selected version on upgrades. Known consumers include [runtime.py](../../../../../src/control_plane_kit_interpreters/docker/runtime.py) and the explicit live fixtures; search source for additional users.

[test_docker_sdk_client.py](../../../../../tests/test_docker_sdk_client.py) protects argument representation, lazy authority construction, bounded helper behavior and inspection semantics. The [synthetic provider fixture](../../../../../tests/live_docker_start_node_contract.py) supplies separately enabled real combined-creation evidence. Fake SDK tests cannot establish current Docker acceptance or justify replay of an uncertain effect.
